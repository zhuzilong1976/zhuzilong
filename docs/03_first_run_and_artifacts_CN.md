## 3. 关键诊断：显著基因数几乎完全由"出度"决定

把两个网络的 24 个基因放在一起看，规律极其整齐：

| 现象 | 数据 |
|---|---|
| 出度 75–216 的基因 | 显著基因数 = **出度 + 1**（CD33 75→76、146→147；YKT6 145→146；BTK 197→198） |
| 出度 > 480 的基因 | 显著基因数 = **1**（只剩被敲除基因自身） |
| 出度 = 0 的基因 | 统计量退化：Control 的 TSHR 给 0 个，MS 的 ACTA2 给 **188 个**（p.adj = 1e-216） |

**解释**：虚拟敲除把目标基因的整行出边置零，直接受影响的就是它的靶基因（数量 = 出度）。流形对齐对这些变化的响应幅度取决于"每个靶基因损失了自身输入的多少比例"——高连接度枢纽的靶基因只损失极小比例，反而通不过显著性阈值；低连接度的基因则相反。出度为 0 时敲除是空操作，统计量进入退化区（Box-Cox + 经验零分布在近乎全零的距离上不稳定），因而可能在 0 与数百个"显著"基因之间随机跳变。

**因此：**

- ❌ 不能按"显著基因数"排名基因（BTK 198 / CD33 147 是出度的函数，不是生物学重要性）
- ❌ MS 网络这一轮结果不可解释（阴性对照 ACTA2 出现 188 个假阳性，且它出度为 0）
- ✅ Control 网络的阴性对照表现正常（0–1 个），说明该网络本身没有系统性问题
- ✅ 出度 ≥ 1 的基因，其显著基因**集合**仍然对应"该基因的直接调控靶标"，可作为假设来源

## 5. 结论

**这一轮的产出是"流程 + 诊断"，不是可发表的生物学结论。**

正面收获：

1. 完整流程在真实数据上跑通，并已按官方规模参数运行
2. 建立了三道质检关卡（出度、阴性对照零分布、显著基因数），并**三次成功拦住了不可用的结果**
3. 查清了结果的度依赖性——这是用该工具时必须先知道的事，也直接决定了后续分析策略

必须解决的问题：

1. 阴性对照的选取要与候选基因**连接度匹配**（不能用出度为 0 或极低的基因）
2. 出度为 0 的基因一律剔除
3. 分析策略要从"按数量排名"改为"按靶基因集合的生物学含义"（富集分析、靶基因重叠、与已知通路一致性）

| **A. 参数调优后重跑** | 设 `nc_lambda = 0.5~1`（启用 strictDirection 强制方向性）、`nc_q = 0.95`，看是否改变度依赖行为；同时改用度匹配的阴性对照 | 每轮约 2 小时 | 有机会让枢纽基因也产生可解释的扰动谱 |
