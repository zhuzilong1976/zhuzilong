# 最严格检验：全基因经验零分布（推翻前面的结论）

日期：2026-09-13　｜　这一步是对 B 方案的最终裁定

---

## 1. 做了什么

前一轮用 23 次敲除估计 z 分数并采用"max_z > 2"作为判据——**这两个选择都不严谨**：

- 用 23 个样本估计每个靶基因的均值和标准差，估计不稳定
- "z > 2"是约定俗成的阈值，没有考虑"在 800 个靶标中取最大值"本身就会抬高统计量

这一轮补齐了唯一的正确做法：**建立经验零分布**。

做法（复用已建网络，无需重新建网，每个网络约 7 分钟）：

1. 对网络中**全部 800 个基因**逐一做虚拟敲除（对照组 7.3 分钟、MS 组 6.3 分钟）
2. 得到完整的 800 × 800 扰动距离矩阵
3. 用全部 800 次敲除估计每个靶基因的 z 分数（而不是 23 次）
4. 以 **776 个非面板基因的 max_z 分布作为经验零分布**
5. 对每个面板基因计算经验 p 值，并按出度 ±20% 做**连接度匹配**的版本
6. Benjamini-Hochberg 多重检验校正

## 4. 前面那个"BTK 只在疾病中出现信号"的结论不成立

上一轮报告 BTK 在 MS 网络中 max_z = 2.72（Control 中 0.50），看起来是漂亮的疾病特异性。用更严格的估计后：

- BTK 在 MS 网络 max_z = 1.83，p = 0.077，FDR 校正后 0.93
- BTK 在 Control 网络 max_z = 0.65，p = 0.31

**BTK 与 Maggi 2023 的"呼应"是估计不稳定性造成的假象，不能作为结论。** 我撤回上一条消息中的这个说法。

## 5. 这个结果说明什么

1. **在 800 基因的小胶质网络规模下，该工具无法把疾病相关的候选基因排在随机网络基因之上。**
2. 面板基因是按"疾病相关性"选出来的，不是按"网络影响力"选出来的——它们不是网络枢纽，所以不出现在扰动谱顶端，这在方法学上是自洽的。
3. 这与 2026 年那篇 8 方法系统评测的结论一致：图方法存在**非特异性**问题（该评测给出的图方法富集特异性仅 0.84×，接近背景）。
4. **本项目至此已经用四道关卡拦住了四个过度结论**：CA/CI 设计（患者完全不重叠）、小规模网络（阴性对照比候选更显著）、度依赖伪影（显著基因数 = 出度 + 1）、以及现在的经验零分布（无一显著）。

## 6. 剩余选项（B 方案已封闭）

| 选项 | 说明 | 可行性评估 |
|---|---|---|
| **A. 参数调优** | `nc_lambda = 0.5~1`（启用 strictDirection）、`nc_q = 0.95`、先验网络约束 | 可做，但**不改变根本问题**：零分布检验仍会要求候选基因显著超过随机基因；2 小时/轮 |
| **C. 扩大到作者规模** | 5,000–7,000 基因 × 500 细胞 × 10 网络（作者用 7,600） | 服务器数小时–1 天。**唯一可能改变结论的路径**，但需接受"可能仍然阴性"的风险 |
| **D. 换用 scTenifoldNet 的两条件比较** | 不做虚拟敲除，直接比较"对照网络 vs 疾病网络"的整体差异（这才是该工具族的设计初衷） | 计算量相同（2 小时/轮），但问的是不同的问题，且不依赖单基因敲除的传播 |
| **E. 接受阴性结果** | 把"虚拟敲除在 800 基因规模下无法区分候选与随机基因"本身写成方法学发现 | 0 成本，且是真话；对领域有价值（呼应 2026 评测） |

## 7. 我的建议

**优先做 D，其次 C。**

理由是：本轮四次尝试都指向同一个根源——**单基因虚拟敲除的效应太弱、被网络整体结构淹没**。而 D（两条件网络比较）直接比较疾病与对照的网络差异，不依赖"敲除一个基因能否撼动整个网络"，是这个工具族最初的设计用途（scTenifoldNet 2020），也与本项目"疾病 vs 对照"的科学问题直接对应。
